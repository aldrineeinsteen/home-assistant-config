# Safe application and recovery

This repository must be applied as a reviewed overlay. It is not a replacement
for the Raspberry Pi's entire `/config` directory. In particular, never delete
or copy over `.storage`, `secrets.yaml`, the database, SSL material, or add-on
data.

The live-instance restoration checklist is in
`inventory/live-instance.yaml`. Home Assistant's official documentation
explains [full and partial backups, downloads, and restores][backups],
[configuration packages][packages], [YAML dashboards][dashboards], and the
[`homeassistant.check_config` action][check-config].

[backups]: https://www.home-assistant.io/common-tasks/general/#backups
[packages]: https://www.home-assistant.io/docs/configuration/packages/
[dashboards]: https://www.home-assistant.io/dashboards/dashboards/#adding-yaml-dashboards
[check-config]: https://www.home-assistant.io/integrations/homeassistant/#action-homeassistantcheck_config

## What is portable

| Repository path | Treatment | Reason |
| --- | --- | --- |
| `packages/` | Copy as new files, then review later changes | Reproducible heating policy and tariff defaults |
| `dashboards/` | Copy as new files | Version-controlled dashboard definitions |
| `themes/` | Copy the directory; `.gitkeep` is only a placeholder | Keeps the configured include valid on a clean checkout |
| `blueprints/` | Copy missing files; compare before replacing | Reusable Home Assistant blueprints |
| `configuration.yaml` | Merge by section; do not replace blindly | The live file can contain host-specific networking and future additions |
| `automations.yaml` | Merge by automation `id`; replace only after an exact diff review | Preserves automations created or edited on the live system after this audit |
| `scripts.yaml` and `scenes.yaml` | Merge; do not replace a non-empty live file with the current empty lists | UI editors may add entries at any time |
| `hacs/` and `inventory/` | Reference only | Restoration manifests, not Home Assistant configuration |
| `.github/`, `.yamllint`, `.gitignore`, and documentation | Repository only | Development and validation support |
| `.HA_VERSION` | Reference only | Generated by Home Assistant; never use it to force an upgrade or downgrade |

Never copy `secrets.yaml`, `.storage`, `home-assistant_v2.db`, logs, certificates,
backups, HACS downloads, or add-on data into Git. On an existing installation,
leave all of those files exactly where they are.

## Before applying anything

1. In Home Assistant, open **Settings > System > Backups** and create a full
   backup. Download a copy to another machine and retain the backup emergency
   kit/encryption key. Do not continue until the backup is visible and
   downloadable.
2. Make a separate copy of the current `configuration.yaml`,
   `automations.yaml`, `scripts.yaml`, and `scenes.yaml`, plus any existing
   `packages`, `dashboards`, and `blueprints` directories. Label it with the
   date and the Git commit being applied.
3. Re-run the inventory checks in `inventory/live-instance.yaml`. If the live
   YAML, dashboards, integrations, HACS resources, or add-ons changed after
   22 July 2026, update the branch and review those differences first.
4. Confirm the required UI-managed integrations and add-ons are healthy. The
   YAML refers to entity IDs supplied by Hive, HomeKit Controller, Ring, Tuya,
   Bambu Lab, Octopus Energy, OpenMediaVault, Pi-hole, Matter, and mobile apps.
   Installing YAML does not create their credentials, pairings, devices, or
   entity registries.
5. Confirm that the four people and the referenced weather, climate, sensor,
   switch, camera, and automation entity IDs exist. Rename mappings in the
   candidate files when the clean installation generated different IDs.

## Non-destructive application to the existing Pi

Use a maintenance window, and apply one batch at a time:

1. Copy the new `packages/` and `dashboards/` files alongside the existing live
   configuration. Copy only missing blueprints; compare any same-named file.
2. Merge these sections from the repository `configuration.yaml` into the live
   file:
   - `homeassistant.packages`
   - `lovelace.dashboards`
   - the hardened `template` entities
   - `group.family`

   Preserve the live `default_config`, `http`, `frontend`, include statements,
   and every unrelated section. In particular, retain the actual trusted proxy
   and any host-specific network values.
3. Merge `automations.yaml` by stable `id` or alias. Retain the five baseline
   live automations (Christmas lights on/off, seed-rack failsafe, Hive hub
   restart, and Ring motion mode manager), then add the boiler-demand and Chris
   room managers from the repository. The automation embedded in
   `packages/heating.yaml` is loaded through packages and must not be duplicated
   in `automations.yaml`.
4. Merge `scripts.yaml` and `scenes.yaml`. They are empty in this audit, so a
   later non-empty live version always wins unless its entries are deliberately
   imported into Git first.
5. Install the HACS integrations listed in `hacs/installed.yaml` through HACS.
   Do not copy `custom_components` from Git. Confirm that the Bambu Lab card
   resource is registered once; the repository leaves Lovelace resources in
   storage mode so HACS remains its owner.
6. Run Home Assistant's configuration check. On Home Assistant OS, the Terminal
   command is `ha core check`; the UI action is
   `homeassistant.check_config`. Do not restart if either reports an error.
7. Review the diff again, then restart Home Assistant once. Check repairs and
   logs before operating the heating controls. Do not reload only part of the
   heating package during first activation because its helpers, templates,
   scripts, timer, schedule, and automation are interdependent.

## First-start checks

Verify these in order after the successful restart:

1. All four dashboards load, with Map available at `/dashboard-map`.
2. `sensor.heating_effective_mode` and its reason are available.
3. The three zone-demand sensors, boiler demand, active zones, requested
   target, and lockout reason are available.
4. The five captured comfort/cutoff defaults are 20°C, 20°C, 20°C, 13°C, and
   6°C. Verify the remaining helper defaults before changing the mode from
   Auto.
5. Hive and each TRV report plausible current temperatures. An unavailable
   zone must not become `0°C` or force demand.
6. Start and cancel Boost while watching the timer; do not change physical
   boiler settings. Confirm that Boost returns to the scheduled/presence mode.
7. Check Home, Sleep, Away, Holiday, and Manual Off transitions. Holiday and
   Off must remain selected until returned to Auto, and frost demand must remain
   possible with a valid cold outside reading.
8. Confirm the existing lighting, seed-rack, Hive restart, and Ring automations
   remain enabled as intended.

## Clean installation

For an exact migration, restoring a full Home Assistant backup is safer than
rebuilding UI-managed state by hand. A full restore carries config entries,
credentials, pairings, entity IDs, dashboards, add-on data, and other state that
must not be committed to Git.

When a deliberate clean rebuild is required instead:

1. Install Home Assistant and the add-ons in `inventory/live-instance.yaml`.
2. Configure the listed built-in integrations through the UI and install the
   four custom integrations through HACS.
3. Recreate people and zones without committing home coordinates or account
   data. Pair devices and restore integration credentials through their normal
   setup flows.
4. Make entity IDs match the YAML, or update all repository references before
   deployment.
5. Apply the portable files using the same merge procedure above, run the
   configuration check, and only then restart.

The sanitized inventories are checklists, not automated imports. This is
intentional: most modern integrations use UI config flows, and their `.storage`
records contain machine-specific or sensitive data.

## Rollback without losing the old configuration

If the configuration check fails, restore the saved copies of only the files
changed in that batch and run the check again; no restart is needed. If the
restart succeeds but behavior is wrong, restore the pre-change YAML files and
directories, run the check, and restart once.

Use the full Home Assistant backup only when file-level rollback is insufficient
or UI-managed state was changed. A restore overwrites the selected parts of the
current system, so select only the required parts and keep the downloaded backup
until the installation has run successfully for several days.
